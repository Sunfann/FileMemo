# 修复记录：文件移动后备注丢失、无法跟踪文件

> 目标项目：**FileMemo（文笺）**（WPF，`net8.0-windows10.0.19041.0`）
> 报告日期：2026-09-29
> 现象来源：用户截图 `PixPin_2026-09-29_16-37-14.png` / `PixPin_2026-09-29_16-36-59.png`

---

## 1. 现象

1. **文件被移动到其它目录后**，左侧列表仍显示旧路径的备注条目，但右侧详情区时间线显示「`deleted 文件缺失，备注保留为孤儿备注`」。
2. **新路径下看不到该文件的备注**（列表 / 文件树均不显示在新位置）。
3. 点击「打开文件」弹出提示：「**文件已被移动或删除，无法打开**」（指向旧路径）。
4. **将文件移回原路径后**，备注又恢复正常显示。

---

## 2. 根因分析

### 2.1 核心缺陷：`OpenByFileId` 恒失败（导致所有 File ID 反查失效）

**位置**: `Interop/NativeMethods.cs` 中的 `OpenByFileId` 方法

**原代码问题**:
```csharp
public static IntPtr OpenByFileId(string volumeRoot, long fileId)
{
    IntPtr hv = CreateFile(volumeRoot, 0, FILE_SHARE_READ | FILE_SHARE_WRITE,
        IntPtr.Zero, OPEN_EXISTING, 0, IntPtr.Zero);  // ❌ 缺少 FILE_FLAG_BACKUP_SEMANTICS
    // ...
}
```

**根本原因**:
- `CreateFile` 打开**目录 / 卷根**时**必须**带 `FILE_FLAG_BACKUP_SEMANTICS`，否则一定返回 `INVALID_HANDLE_VALUE`。
- 这导致：
  1. `OpenFileById` 拿不到有效的卷句柄 → 始终失败；
  2. **同卷 File ID 反查路径**（`TryLocate`）完全失效；
  3. **USN Journal 父目录解析**（`ResolveDirectoryPath`）也失败；
  4. 表现为：**文件一旦移动，任何基于 File ID 的路径恢复都做不到**，只能等文件回到原路径才能匹配上旧备注。

**修复要点**:
- 增加 `FILE_FLAG_BACKUP_SEMANTICS` 标志；
- 优先使用**卷 GUID 设备路径**（`\\?\Volume{guid}\`），其次尝试 `\\.\C:`，最后退回 `C:\`；
- 新增 `VolumeHandleCandidates` 生成候选路径并去重。

### 2.2 监听器缺陷：跨目录移动被误判为删除

**位置**: `Services/FileWatcherService.cs` 中的 `OnDeleted` 处理器

**原逻辑问题**:
- FileSystemWatcher 对跨目录移动的报告方式：`Deleted`(源) + `Created`(目标)；
- `OnDeleted` 直接标记备注为 `Offline=true` 并写入「`文件缺失，备注保留为孤儿备注`」时间线；
- **从未在删除前尝试用指纹找回**（`Reconcile`），导致把「移动」当成「永久丢失」。

**修复**:
- `OnDeleted` 中先调用 `Reconcile(fr)` 尝试找回；
- 命中则直接返回（不标记孤儿）；
- 未命中再走孤儿流程。

### 2.3 缺少 Created 事件处理（移动到位时无法捕获）

**位置**: `Services/FileWatcherService.cs`

**问题**:
- 只订阅了 `Renamed` / `Deleted` / `Changed`，**没有订阅 `Created`**；
- 当文件被移动到已监听的目標目录时，`Created` 事件被忽略，备注无法跟随到新路径。

**修复**:
- 新增 `OnCreated` 处理器：用 `GetNtfsIdentity` 取 File ID → `_repo.FindByFileId` 精确命中 → 调用 `RelocateToNewPath` 更新路径；
- 仅采用 File ID 这一强信号，避免把「复制出来的副本」误绑到原备注。

### 2.4 UI 未刷新（后台路径变化不通知前端）

**位置**: `Services/FileWatcherService.cs` + `Views/MainWindow.xaml.cs`

**问题**:
- 后台监听发现移动/重命名/校正后，**没有通知 UI 刷新**列表与文件树；
- 用户看到的仍是旧数据，直到手动刷新或重启应用。

**修复**:
- `FileWatcherService` 新增 `public event Action? DataChanged`；
- 每次路径变化（`ReconcileAll` 命中、`OnRenamed`、`OnCreated`、`OnDeleted` 找回、`OnChanged` 内容变化）后调用 `RaiseDataChanged()`，通过 Dispatcher 通知 UI 线程；
- `MainWindow.OnLoaded` 订阅该事件 → 调用 `_vm.Refresh()` 刷新全部集合，并尽量保留当前选中项。

## 3. 修改文件清单

| 文件 | 变更内容 |
|---|---|
| `Interop/NativeMethods.cs` | 重写 `OpenByFileId`：增加 `FILE_FLAG_BACKUP_SEMANTICS`、卷 GUID 优先、新增 `VolumeHandleCandidates` |
| `Services/FileWatcherService.cs` | 新增 `DataChanged` 事件；`OnCreated` 处理器；`RelocateToNewPath`；`RaiseDataChanged`；`OnDeleted` 先 `Reconcile` 再孤儿；各事件处理后通知 UI |
| `Views/MainWindow.xaml.cs` | 新增 `OnWatcherDataChanged` 回调；`OnLoaded` 订阅 `App.Instance.Watcher.DataChanged` |

### 3.1 编译修复（CS0070）

初次实现误用空条件运算符订阅事件：

```csharp
App.Instance.Watcher?.DataChanged += OnWatcherDataChanged;  // ❌ CS0070：事件不能出现在 ?. 左侧
```

**原因**：C# 规定事件（event）只能出现在 `+=` / `-=` 的左侧，且不能用 `?.` 作为条件访问的目标。

**修复**：改为显式判空后再订阅：
```csharp
var watcher = App.Instance.Watcher;
if (watcher != null) watcher.DataChanged += OnWatcherDataChanged;
```

## 4. 预期效果

- **运行时移动**（USN / FSW 在线）：
  - 同卷移动：File ID 精确命中 → 备注路径即时更新，时间线记录 `moved`；
  - 跨卷移动：若内容哈希唯一也可命中（可选）；
  - UI 自动刷新，新路径下立即显示备注。
  
- **应用关闭期间移动**（离线移动）：
  - 下次启动时 `ReconcileAll()` 全量校正 → 找到则路径更新，找不到保持孤儿；
  - 「打开/定位」按钮也会先尝试 `Reconcile` 再操作。

- **文件被彻底删除**：
  - 明确提示「文件缺失，备注保留为孤儿备注」，不会误删备注本身。

## 5. 验证建议

1. **热移动测试**：
   - 为某 GPX 文件添加备注 → 在资源管理器把它拖到子目录 `s\` → 观察：
     - 列表路径应自动更新为新位置；
     - 时间线出现 `moved` 记录；
     - 点「打开文件」能正常打开。

2. **冷移动测试**：
   - 为某文件添加备注 → 关闭应用 → 移动文件到别处 → 重新打开应用：
     - 启动时应自动校正路径；
     - 列表显示新路径，旧路径不再出现。

3. **复制 vs 移动区分**：
   - 复制一份同名同内容文件到别处 → 原备注不应跟随副本（只有 File ID 命中才算移动）。

4. **删除确认**：
   - 删除已备注文件 → 备注应保留为孤儿状态，时间线记录 `deleted`。

## 6. 关联修复

本修复与之前的两处改动协同工作：
- `FingerprintService.TryLocate`：提供按 File ID / 哈希的路径找回能力；
- `MainWindow.EnsureFileRefCurrent` / `FloatingNoteWindow.ResolveCurrentPath`：打开/定位前先校正路径。

现在整个链路闭合：**NTFS File ID 可正确打开 → 实时监听捕获移动 → 离线校正弥补空窗期 → UI 即时刷新**。
